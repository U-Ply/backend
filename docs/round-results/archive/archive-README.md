# docs/round-results/ 읽는 법

이 폴더에는 성격이 다른 두 세대의 리포트가 섞여 있다. **같은 칸에 놓고 비교하면 안 된다.**
§8.1 은 서로 다른 환경 ID 에서 측정한 값을 직접 비교하지 말라고 정한다.

| | 1세대 `L1-*`, `LEAK-*` | 2세대 `V0`~`V3` |
| --- | --- | --- |
| 일시 | 2026-08-21 | 2026-08-24 이후 |
| 실행 | `scripts/test/acceptance.sh` | `./gradlew test` (JUnit + Testcontainers) |
| DB | 공유 개발 DB `coupon_db` | 매 실행 새로 뜨는 MySQL 컨테이너 |
| 검사 행 | 99,930 / 127,635 | 1 / 7 / 10 |
| 부하 조건 | 재고 30 / 요청 100 | 재고 10 / 요청 30 (§5.2) |
| 규칙 수 | 14 | 15 |
| runId | 사람이 지정 | 실행마다 자동 생성 |

## 1세대를 그대로 읽으면 안 되는 이유

### 더미데이터가 검사 대상에 포함돼 있다

검증 배치는 캠페인으로 거르지 않고 테이블 전체를 훑는다. 개발 DB 에 있던 쿠폰
99,900 건이 회차 결과에 함께 들어갔다. `L1-BASE-01` 은 그 값을 빼기 위한 회차 전
기준선이다. 1세대 리포트의 위반 수를 읽을 때는 반드시 `L1-BASE-01` 을 먼저 본다.

### `REC-01` 이 리포트에 아예 없다

1세대는 대사 배치를 함께 돌리지 않았다. 그래서 `REC-01` 행이 생기지 않았고,
미실행 수는 0 이라 "전부 통과" 로 읽힌다. 검사하지 않은 것이 **규칙이 사라지는
형태로** 통과가 된 것이다.

이것이 가설이 아니라는 증거가 같은 폴더에 있다.

```
L1-V2-01    (01:30)  규칙 14 · REC-01 없음        · 판정 통과
LEAK-V2-01  (08:10)  규칙 15 · REC-01 위반 1건    · 판정 불일치
                     redis=0, db=1, diff=-1
```

같은 V2 경로다. `L1-V2-01` 의 "통과" 는 조용한 통과였다.

2세대는 `RoundReportAssert.assertRuleSetComplete()` 가 리포트에 `REC-01` 과
`CLOCK-01` 이 실제로 나타났는지를 검사한다. 같은 형태가 다시 통과할 수 없다.

### `CLOCK-02` 가 잘못 기록돼 있다

`L1-V2-01` 과 `L1-V3-01` 은 `CLOCK-02` 를 `Redis 경로 회차 아님 (N/A)` 로 남겼다.
§14.3 에 따르면 V2·V3 는 Lua 가 반환한 시각을 `issued_at` 에 쓰므로 CLOCK-02 를
**실제로 판정해야 한다.** 그 회차는 `usesRedisClock` 판정이 들어가기 전에 돌았다.

같은 날 `LEAK-V2-01` 부터는 실제로 판정한다.

```
L1-V2-01     CLOCK-02  Redis 경로 회차 아님 (N/A)
LEAK-V2-01   CLOCK-02  redis_drift=-0.002s tol=0.300s  통과
```

## 그래서 어떻게 쓰는가

- **§11 비교표에는 2세대(`V0`~`V3`)만 넣는다.**
- 1세대는 지우지 않는다. §2.7 — 실패도 원인과 함께 남긴다. 특히
  `L1-V2-01` → `LEAK-V2-01` 의 뒤집힘은 "검사하지 않은 것을 통과로 기록하면
  어떻게 되는가" 의 실제 사례라 보존 가치가 있다.
- 1세대 수치를 인용할 때는 위 세 가지 한계를 함께 적는다.

## V0 결과는 실행마다 다르다

§5.4 가 "스레드 스케줄링에 따라 매 실행에서 동일하게 발생한다고 보장할 수 없으므로
반복 실행 결과를 기록한다" 고 못 박는다. 실제로 그렇다.

```
INV-03  remaining=6  expected=3   (issued 7)
INV-03  remaining=20 expected=9   (issued 21)
```

V0 의 위반 수는 판정이 아니라 §11 비교표의 기록 항목이다. 리포트 판정도
`BASELINE` 으로 나오며 통과·실패로 찍지 않는다.
